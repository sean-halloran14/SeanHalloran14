    • One nightly pipeline for a company's sales data

      A vending and food-service company's reporting ran on 46 separately scheduled pipelines, dataflows and notebooks that had grown one report at a time. I rebuilt it as a single object-oriented Python pipeline in Microsoft Fabric: each night it downloads 56 API reports, keeps the raw copies, and builds 58 cleaned and 15 business tables, checking and logging itself as it goes. It runs in about 13 minutes instead of roughly 6 hours of daily run time, fills in missed days on its own, and keeps every business rule in one documented place.

    • Migrating a live workspace without breaking reports

      Moving a company's live reporting onto a new design without breaking anyone's reports. I rebuilt the work in a separate test copy, kept the business rules the original had established, and compared the new tables with the old ones value by value while both ran side by side. The approach is now written up as a repeatable pattern, and the company's other data sources (CRM, accounting, point of sale) are starting to move the same way.

    • A pipeline that reports on itself

      Checking whether a night's data had loaded used to mean looking through 46 run histories. I built diagnostics into the pipeline: every run logs each report and table (rows loaded, freshness, and warnings such as a sudden drop in rows or an empty download) and marks the whole run failed if anything is missing, so problems are known the same morning. A Power BI report shows the log, and another flags mismatches in an operations team's spreadsheet so they can fix them at the source.

    • Writing it down so others can use it

      A data platform only helps if people can use it and change it safely. For the pipeline rebuild I wrote three documents: a plain-language overview for managers comparing the old and new setups, an 18-page analyst guide with recipes for querying the tables, building Power BI reports and adding features through a test copy, and a 50-page developer reference covering every business rule, table and class. Each rule lives in one documented place, so someone new can find it and see how it works.
